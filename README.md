## 项目背景与硬约束

会展场馆的排期核对目前靠人工翻服务台记录、Excel 台账、共享盘文件三处来源，交叉比对费时且易漏。本项目按"数智化转型"方法论完成了从业务挖掘 → 行业分析 → 流程再造 → 设计方案 → 技术架构 → MVP 开发 → 评测验证的完整闭环。

**三条业务硬约束**（贯穿所有设计决策）：

| 硬约束 | 系统解法 |
|--------|----------|
| 不做系统改造、不自动写回 | 三源**只读**归集，AI 只输出候选提示，永不直接锁档 |
| 结论必须人工把关 | 草稿创建前**强制中断**弹人工确认单，5 个确认门全部保留 |
| 数据隐私与审计 | 字段级脱敏、按角色授权、问答/工具轨迹/确认单全量留痕 |

> 因此本系统的 Agent 是**被严格约束的 Agent**：能查、能比对、能出草稿，但"生效"这个动作只属于人。

## 系统架构

```
┌─────────────────────────────────────────────────────────────┐
│                     管理后台（FastAPI SSR）                   │
│   登录 RBAC │ 知识库 │ 提示词模板 │ 档期问答 │ 审计 │ 用户管理  │
├─────────────────────────────────────────────────────────────┤
│                    Agent Harness（执行循环）                  │
│  系统提示词（模板可配置）+ 固定页脚强制追加 + 5 轮上限          │
│  ┌────────── ReAct 决策 ──────────┐  ┌──── 风控三层防线 ────┐ │
│  │ LLM Function Calling（6 工具） │→│ precheck 双凭据防跳步 │ │
│  └────────────────────────────────┘  │ 草稿创建强制中断确认   │ │
│                                     │ 确认后重跑双校验      │ │
│                                     └──────────────────────┘ │
├─────────────────────────────────────────────────────────────┤
│ 工具层（tools.py，规则引擎不走 LLM）│ RAG 层（BM25+向量混合）  │
├─────────────────────────────────────────────────────────────┤
│        SQLite（ORM 可切 PG）：知识库/审计/草稿/确认单/日志      │
└─────────────────────────────────────────────────────────────┘
```

- **RAG**：BM25 + 向量双路召回，切片带 `文档名/版本/切片号` 溯源标记，引用必须能点回原文位置
- **冲突判定走规则引擎**，不让 LLM 判冲突——LLM 只负责理解意图和组织语言，判定口径必须可复现
- **LLM 供应商可切换**：`LLM_PROVIDER` 环境变量切换 `mock`（离线）/ `openai` / `dashscope` / `deepseek` / `moonshot`

## 智能体能力：六工具执行循环

Agent 每轮自主决策调用工具，轨迹全量写入 `agent_run_logs` 决策日志表：

| # | 工具 | 作用 | 风控 |
|---|------|------|------|
| 1 | `search_kb` | 知识库检索排期制度口径 | 只读 |
| 2 | `get_schedule` | 查已确认档期（含演示种子 A001） | 只读 |
| 3 | `check_missing_fields` | 缺项清单（必填字段逐项核对） | 只读 |
| 4 | `check_conflict` | 时间窗/装卸口/进撤场多维冲突检测 | 只读；硬冲突直接 **blocked** 终止 |
| 5 | `create_schedule_draft` | 创建档期草稿 | **强制中断** → 人工确认单（AgentConfirmation）→ 确认后**重跑 3+4 双校验**再执行 |
| 6 | `submit_for_review` | 草稿提交人工复核 | 仅转状态，不生效 |

**防跳步设计**：第 5 步要求第 3、4 步新近颁发的 HMAC precheck token（5 分钟有效），模型想跳过校验直接建草稿会被服务端拒绝；确认等待期间档期若被他人占用，恢复执行时会重新检出冲突并拒绝创建。

**中断恢复演示**（真实轨迹）：

```
轮1 search_kb ok → 轮2 get_schedule ok → 轮3 check_missing_fields ok
→ 轮4 check_conflict ok → 轮5 create_schedule_draft pending_confirm 🛑
   （人工点击"确认"）
→ 恢复：check_missing_fields ok → check_conflict ok（复检）
   → create_schedule_draft ok（draft id=6）→ submit_for_review ok ✅
```

**硬冲突拦截演示**（与已确认档期 A001 时间重叠 + 装卸口 B 被占）：

```
轮4 check_conflict blocked 🚫 → 终止，不产生确认单、不创建草稿
输出：time_overlap（业务规范 1.2）+ dock_conflict（业务规范 2.2），转人工处理
```

## 管理后台功能

| 角色 | 账号（演示） | 权限 |
|------|--------------|------|
| 管理员 | `admin / admin123` | 知识库上传/重建索引、提示词模板版本管理、对话审计（含标记）、Agent 轨迹统计、用户管理 |
| 项目协调员 | `coord / coord123` | 档期问答（普通/智能体模式）、草稿创建与确认、导出交接单 |
| 一线员工 | `staff / staff123` | 仅问答与查看；服务端拒绝创建草稿 |

- **问答审计**：每轮保留提问原文、召回切片、LLM 原始回答全文、提示词模板版本号；支持人工标记风险（冲突误判/越权承诺/口径失效）
- **导出（v1.3）**：草稿一键导出 Markdown 交接单（带交接确认清单）和 ICS 日历（TENTATIVE 占位、带【草稿·不生效】前缀，可导入 Outlook/企业微信日历）
- **Agent 轨迹统计（v1.3）**：`GET /api/admin/audit/agent-stats` 聚合工具调用频次、状态分布、平均耗时、中断确认率

## 快速开始

### 环境要求

- Python 3.10+；其余依赖见 `requirements.txt`（FastAPI / SQLAlchemy / uvicorn，离线 mock 模式无需任何 API Key）

### 安装与启动

```bash
git clone https://github.com/iiqi108xi/venue-scheduling-demand-change.git
cd venue-scheduling-demand-change
pip install -r requirements.txt

# 启动管理后台（默认 mock 供应商，离线可跑）
cd src/admin
python -m uvicorn main:app --host 127.0.0.1 --port 8000
# 端口被占用/被系统保留时换一个即可，如 --port 8500
```

浏览器打开 `http://127.0.0.1:<端口>/login`，用上表演示账号登录。

### 运行评测

```bash
cd src/admin
# 链路模式（离线）：校验 HTTP/轨迹/页脚/中断规则
python -m eval.run_eval --mode plumbing --base-url http://127.0.0.1:8500 --user coord --password coord123
# 语义模式：接真实大模型后按关键词+工具链子序列判分
python -m eval.run_eval --mode semantic ...
```

### 测试

```bash
python -m unittest discover -s tests -v   # 12 条单元测试
```

## 演示流程（5 分钟走通）

1. **口径咨询**（1 轮收敛）：问答页提问"上海会展中心 3 天档期预订标准是什么" → 智能体第 1 轮 `search_kb` 后直接引用知识库作答，回答带 `[来源N]` 引用与人工复核页脚
2. **完整预订流**：切"智能体模式"，提交副馆 12-30 草稿 → 第 5 步强制中断弹确认单 → 点击确认 → 系统复检后创建草稿并提交复核
3. **硬冲突拦截**：提交与 A001 重叠的主馆档期 → 第 4 步 blocked，输出冲突候选与口径编号，转人工
4. **越权演示**：登录 staff 尝试创建草稿 → 服务端 403 拒绝
5. **审计回查**：admin 登录 → 对话审计看完整留痕 → 导出草稿交接单（.md）与日历（.ics）

| 指标 | 现状 | 试点目标 |
