# Venue Scheduling Demand Change

> 场馆排期与需求变更 · AI 数智化辅助系统

面向会展场馆的排期与需求变更场景，基于"只读关联 + AI 提示 + 人工确认留痕"的模式，在不改造现有业务系统的前提下，提升排期核对效率、降低交接差错、保留完整审计链路。

本项目为课程演练产出，包含业务挖掘、行业分析、现状/数智化后流程图、设计方案与报价单全套文档。

## ✨ 功能特性

- **三源只读归集**：统一关联编号串起服务台、台账、文件库，字段级来源可回溯
- **冲突候选检测**：时间窗 + 装卸口 + 进撤场时长多维检测，给出候选、依据与置信度
- **缺项清单生成**：一页清单 + 可点击来源位置，减少逐项查找时间
- **版本智能判定**：有效期 + 确认状态双条件，不靠文件名猜最新版
- **双时间戳兜底**：业务发生时间与系统接收时间双写，读取失败快照保留
- **人工复核留痕**：采纳/驳回/改值全留痕，原值保留、改值必填原因
- **字段级脱敏**：敏感字段按角色授权，跨企业资料按授权范围访问
- **审计追溯**：谁查过、用哪个版本、谁确认、改了什么，一键可查

## 🚀 快速开始

### 环境要求

- Python 3.10+
- Git

### 安装

```bash
# 克隆仓库
git clone https://github.com/iiqi108xi/venue-scheduling-demand-change.git
cd venue-scheduling-demand-change

# （可选）创建虚拟环境
python -m venv venv
# Windows: venv\Scripts\activate
# macOS/Linux: source venv/bin/activate

# 安装依赖
pip install -r requirements.txt
```

### 运行

```bash
# 运行示例
python examples/demo.py

# 或直接运行入口
python -m my_tool.main
```

### 测试

```bash
pytest tests/
```

## 🎯 核心思路

> **不加新系统、不做写回，只在现有工具上加一层只读关联 + 提示 + 人工确认留痕。**

三个硬约束的解法：

1. **费钱费时间** → 零系统改造，复用现有工具，一个批次试点、四周交付
2. **人工审核** → 不是去掉人，是把"逐项找"变成"逐条判"，5 个确认门全部保留
3. **数据隐私** → 字段级脱敏、最小可见、只读、可审计、三不原则（不留副本/不训练/不出客户环境）

## 📊 预期效果（试点目标）

| 指标 | 现状 | 试点目标 |
|------|------|----------|
| 单均核对时间 | ~35 分钟 | ~10 分钟复核 |
| 冲突漏识别 | 靠人工逐项比对 | AI 候选 + 人工判定 |
| 版本判定方式 | 靠文件名猜 | 有效期 + 确认状态双条件 |
| 交接信息完整度 | 只发"已处理" | 四项必填（接收人/版本/未确认项/截止时间） |
| 审计追溯 | 只留最终摘要 | 全过程可查（谁查/哪个版本/谁确认/改了什么） |
