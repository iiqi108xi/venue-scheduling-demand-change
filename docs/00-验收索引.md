## 三、逐项看点（打开后指给老师看什么）

### 1. 六人访谈记录
- 六人：顾明岚（业务负责人）、林亦舟（一线服务专员）、唐映秋（项目流程协调员）、秦芮（数字化工程师）、傅景（审核与质量负责人）、叶书（客户协同代表）。
- 每人含：角色介绍 → 核对重点 → 访谈问答（Q/A）→ 事实记录（`dlg-venue-schedule-f00` 起编号）。
- 三格式分工：md 供阅读、json 供程序读取、csv 供 Excel 筛选；**同一数据源，不是三份不同内容**。

### 2. 项目基本简报（4 个文件）
- `1-客户简报`：企业与项目背景、客户原话、目标/基线/样本/边界、六角色诉求。
- `2-现状信息请求表`：向六个角色分别索取哪些记录、用途、脱敏与版本要求。
- `3-业务发现访谈问题库`：按角色给出切入点问题 + 追问。
- `4-利益相关者资料与分工`：六人职责、接收谁的输入、向谁交接。

### 3. 典型事件采访
- txt 是**可直接下载的原始对话稿**：第一轮讲事件（十月东区装卸口撞期）、第二轮量化痛点、第三轮拍板权/例外/验收。
- 量化数字：45 单/月、35 分钟/单、六七成重复核对、月退回 7–8 单、例外通道多 2–3 天、30 个样本回放。
- docx 是 AI 整理版：访谈目的 → 事件概述 → 痛点量化 → 拍板权与验收 → 事实清单 → 待核实项。

### 4. 行业分析
- 结构：摘要 → 行业概况 → 业务链路与价值分布 → 核心痛点（重复核对/版本责任链/人工审核压力）→ 数字化趋势 → 东浩优势·机会·约束 → 风险 → 结论。

### 5. 两份流程图
- **改造前**：六条泳道＝六位受访者，五阶段 18 步，9 个交接点，3 个异常出口；**已融入典型事件的装卸口撞期卡点**；标准符号（矩形执行 / 菱形判断 / 双线人工确认 / 粗红边不可逆 / 胶囊触发 / 文档形对外输出）。
- **改造后**：19 步，AI 只读归集与候选提示，5 个人工门保留，不可逆动作前有校验。
- PNG 直接贴作业；HTML 可点节点看输入/输出/失败方式/证据编号。

### 6. 需求分析方案
- 痛点清单 PL-1~5（每条带证据编号）。
- AI 改造 AI-1~8 **带 P0/P1/P2 优先级**，写回类明确列为"不做"。
- 需求边界：范围内 4 条、范围外 5 条排除；FR-1~8 规格。
- **五、需求追溯矩阵**：痛点 → AI 改造 → 功能需求 → 验收标准，四层闭环。
- 六、验收标准清单 AC-1~8（30 样本回放、来源可追溯、人工门签字完整等）。

### 7. 详细项目设计方案
- 五条设计原则（只读优先、规则为主模型为辅、人在环路、可审计、零改造部署）。
- 四层架构 + M1~M6 模块 + 四个关键设计决策（含"为什么只读""为什么规则优先"论证）。
- 技术选型、安全与隐私、四周实施计划与里程碑门禁、风险回退。

### 8. 报价与投入产出测算
- 计价方式：功能点/规模（44 FP × ¥1,200 + 实施 ¥9,000）。
- 三档：低配 ¥28,000 / 中配 ¥61,800（推荐）/ 高配 ¥128,000，升级可全额抵扣。
- **商业论证链**：4.1 报价及范围 → 4.2 月运行成本 ¥800 → 4.3 业务量/节省时间/采用率 80%/兑现率 60% → 4.4 首年净收益、ROI、回本期（基准首年 −¥30,096、约 21 个月、稳态 ROI≈162%）→ 4.5 待验证假设 A-1~6。
