# 13 · 演示操作手册

> 面向验收方/老师：按角色把系统"全部走一遍"，每步给出**操作**、**预期结果**和**观察点**。
> 全程约 5–8 分钟。前置：服务已启动（默认 `python -m uvicorn main:app --port 8500`）。

---

## 零、启动与登录

```bash
cd venue-scheduling-demand-change/src/admin
python -m uvicorn main:app --host 127.0.0.1 --port 8500
```

浏览器打开 `http://127.0.0.1:8500/login`。

| 账号 | 密码 | 角色 | 演示用途 |
|------|------|------|----------|
| `admin` | `admin123` | 管理员 | 知识库、提示词、审计、用户 |
| `coord` | `coord123` | 项目协调员 | 问答 + 智能体 + 草稿确认（主演示账号） |

## 一、演示 1：口径咨询（验证"只答制度、给出来源"）

1. 用 `coord` 登录 → 进入「档期问答」
2. 模式保持「普通问答」，输入：`上海会展中心 3 天档期预订标准是什么`
3. 观察点：
   - 回答**第 1 轮即收敛**，不追问、不乱调工具
   - 每条结论后有 `[来源N] 《场馆档期业务规范.md》v1/切片#n` 引用
   - 结尾固定页脚：**"⚠️ 以上为系统候选提示，最终结论需要人工复核确认。"**

补充提问（陷阱题）：`展馆能保证给我们多少展位？` → 预期回答"制度中未找到对应口径，请人工复核"，**不得承诺数量**。

## 二、演示 2：完整预订流（验证"强制人工确认"）

1. 同一页面切到「智能体模式」
2. 填写草稿参数：
   - 项目：`演示展`　主办方：`华辰会展`　展馆：`副馆 Hall-B`　装卸口：`D`
   - 活动：`2026-12-30 09:00 ~ 2026-12-30 16:00`
   - 进撤场：`2026-12-30 06:00 ~ 2026-12-30 18:00`
3. 提问：`帮我预定下个月上海场馆档期`
4. 观察点（轨迹应逐步出现）：
   ```
   轮1 search_kb → 轮2 get_schedule → 轮3 check_missing_fields
   → 轮4 check_conflict → 轮5 create_schedule_draft  🛑 pending_confirm
   ```
5. 页面弹出**人工确认单**（草稿内容 + 原始提问），点击「确认」
6. 观察点（恢复执行）：
   ```
   check_missing_fields（复检）→ check_conflict（复检）
   → create_schedule_draft ok（生成草稿，状态 draft/pending_review，不生效）
   → submit_for_review ok
   ```
7. 说明要点：**确认前不会创建任何草稿**；确认后系统会重跑两道校验（防止等待期间档期被别人占了）。

## 三、演示 3：硬冲突拦截（验证"规则引擎把关"）

1. 仍在智能体模式，填：`主馆 Hall-A`，装卸口 `B`，活动 `2026-11-19 09:00 ~ 16:00`
2. 提问：`帮我预定主馆档期`
3. 观察点：
   - 轨迹停在 `轮4 check_conflict **blocked**`，**不弹确认单、不建草稿**
   - 输出两条冲突候选 + 口径编号：
     - `time_overlap`：与已确认档期 A001《春季设备展》时间窗重叠 → 业务规范 1.2
     - `dock_conflict`：装卸口 B 在进撤场窗口被 A001 占用 → 业务规范 2.2
   - 回答明确"按风控规则禁止创建草稿，转人工处理"

## 五、演示 5：管理员视角（知识库 / 审计 / 导出 / 统计）

用 `admin` 登录，依次打开：

| 页面 | 操作 | 观察点 |
|------|------|--------|
| 知识库 | 上传一份 `.md` 制度文件 | 自动切片 + 向量化，状态 `ready`，可重建索引 |
| 提示词模板 | 查看版本列表 | 每次修改生成新版本号，问答记录里带 `prompt_template_version` |
| 对话审计 | 打开刚才三条演示的会话 | 提问原文 / 召回切片 / LLM 原始回答**全文**留存，可标记风险 |
| 草稿 | 对草稿点「导出交接单」 | 下载 `draft-6.md`：字段 + 交接确认清单 + "不生效"声明 |
| 草稿 | 点「导出日历」 | 下载 `draft-6.ics`，导入日历后事件状态为"暂定"，标题带【草稿·不生效】 |
| 轨迹统计 | `GET /api/admin/audit/agent-stats` | 工具调用频次/状态分布/平均耗时/中断确认率 |

> 导出与统计接口的实测结果见 [12-测试与验证报告](12-测试与验证报告.md) 第四节。

## 六、常见提问的现场应答

| 老师可能问 | 应答要点 |
|------------|----------|
| 为什么不让 LLM 判冲突？ | 冲突是规则问题，口径必须可复现可审计；LLM 只做意图理解与表达。判定看 `tools.check_conflict`，每条结论绑定规范编号。 |
| 如何防止模型跳过校验直接建草稿？ | 双 precheck token（HMAC，5 分钟）+ 工具层校验调用顺序，跳步直接拒绝；这条有评测用例覆盖。 |
| 确认后为什么还要复检？ | 确认等待期间档期可能变化，恢复时重跑可捕获新冲突（避免"确认了一个已过期的判断"）。 |
| 数据安全怎么保证？ | 三源只读不回写、字段级脱敏、按角色授权、全量审计；LLM 侧不留训练副本。 |
| 这套东西真能上线吗？ | 本版本是 MVP：单机 SQLite、无并发锁、连接器为样本数据。上线需补并发控制、真实连接器、压测与灰度（见报告第七节遗留问题）。 |

## 七、演示失败时的应急

| 现象 | 处理 |
|------|------|
| 端口绑定失败 `WinError 10013` | 端口被系统保留，换 `--port 8500/8600` 等 |
| 页面能开但接口 502 | 检查是否有多层代理拦截 localhost；命令行用 `curl --noproxy '*'` 验证 |
| 问答回答很模板化 | 当前是 `LLM_PROVIDER=mock` 离线模式，属预期；设真实 Key 后语义自然 |
| 草稿列表为空 | 演示数据在 `admin.db`，删除后重启会由 `init_db()` 重新播种 A001 |
