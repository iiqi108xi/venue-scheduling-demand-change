一、系统概述

本系统为「场馆档期申请只读核对助手」MVP：FastAPI + Jinja2 服务端渲染管理后台，内置 RAG 问答、规则引擎冲突检测、Agent 执行循环（Harness，最多 5 轮）、三处人工确认点（角色门禁、强制中断确认单、提交人工复核）、全量审计留痕与 RBAC 三角色权限。业务硬约束：只读归集、AI 只提示不写回、所有结论人工把关。

1.1 组件清单

组件位置说明
管理后台（SSR）src/admin（main.py 入口）登录/问答/草稿/审计/知识库/用户管理
Agent 执行循环src/admin/harness.py、agent.py6 工具 Function Calling，强制中断

二、部署上线

2.1 环境要求

1. Python ≥ 3.10（验证环境 3.13）；2. 内存 ≥ 512MB（无 GPU 要求）；3. 端口：默认 8123，Windows 下若落在 Hyper-V 保留段（netsh int ipv4 show excludedportrange protocol=tcp 可查）换任意空闲端口，代码无硬编码；4. 外网：可选——LLM_PROVIDER=mock 时完全离线可跑。

2.2 部署步骤

1. 获取代码：git clone https://github.com/iiqi108xi/venue-scheduling-demand-change.git

2. 安装依赖：pip install -r requirements.txt

3. 启动服务：cd src/admin && python -m uvicorn main:app --host 0.0.0.0 --port 8500

4. 验证：curl http://127.0.0.1:8500/login 返回 200；浏览器打开 http://<主机IP>:8500/login

5. 冒烟：按 docs/13-演示操作手册 走通「口径咨询 → 预订流（强制中断）→ 确认创建」三步即视为部署成功。

三、日常运行

3.1 账号与角色

账号角色权限
admin / admin123管理员全部功能：知识库、提示词模板、审计、用户管理、草稿创建
staff / staff123一线员工问答、查询、草稿确认（不可创建草稿）
coordinator项目流程协调员可创建草稿（试点期由管理员代管）

上线后第一件事：修改两个默认密码（管理员页面「用户管理」），并为真实经办人创建 coordinator 账号。

3.2 服务管理

1. 前台运行：python -m uvicorn main:app --port 8500；2. 生产建议：Windows 注册为计划任务 / NSSM 服务，或 Linux systemd 单元，崩溃自动拉起；3. 日志：uvicorn 标准输出 + agent_run_logs 表（每轮工具调用的参数/耗时/状态/结果摘要，结果摘要截断 500 字符防撑爆）。

3.3 备份与数据管理

1. 每日备份 src/admin/data/admin.db（单文件 SQLite，直接复制即可，建议保留 30 天滚动）；2. 知识库文档上传后切片入库，原始文件建议同目录归档；3. 审计数据只增不改，随库备份。

四、故障处理

现象排查处置
端口启动失败（WinError）netsh 查 Hyper-V 保留段换端口启动，代码无硬编码
问答始终返回「未找到对应口径」知识库为空或文档状态非 ready/admin/kb 上传制度文档，等待状态 ready
LLM 调用超时/报错LLM_PROVIDER / API Key 配置临时切 mock 保业务可用（回答自动标注演示模式）
确认单无法确认（409）状态机：confirmed 不可重复处理 / 30 分钟超时视为放弃重新发起预订流程生成新确认单
检索质量下降faiss 不可用已降级 NumPypip install faiss-cpu 恢复向量索引

五、回退方案

1. 系统为只读辅助层，不写回业务系统——直接停止 uvicorn 进程即完成回退，原业务（服务台/台账/文件库）零影响；2. 数据回退：恢复 admin.db 备份文件后重启；3. 版本回退：git checkout 到上一发布 tag 重启；4. 回退后核对审计页最后一条记录时间，确认无未完成确认单悬挂。

六、安全注意事项

1. 生产必须改默认密码并启用 HTTPS（反向代理终止 TLS）；2. LLM_API_KEY 等凭据只放环境变量，不进代码库（.gitignore 已拦截 credentials*.json / .env）；3. 管理员页面（审计/用户/提示词模板）仅 admin 可达；4. 对话与工具轨迹全量留痕且只增不改，满足「谁查过、用哪个版本、谁确认」的可追溯要求。
